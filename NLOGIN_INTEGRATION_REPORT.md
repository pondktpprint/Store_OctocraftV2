# nLogin Integration & Environment Configuration Report

## Overview
A comprehensive integration with the external nLogin database has been established to allow server administrators safe, read-only access to player records. Simultaneously, the backend configuration system was refactored to enforce strict environment variable parsing, guaranteeing credential safety.

## Configuration Enhancements
1. **Strict Startup Validation**: Introduced `backend/config/env.js` which parses `.env`. If critical database credentials (e.g., `STORE_DB_PASSWORD` or `NLOGIN_DB_PASSWORD`) or tokens (`JWT_SECRET`) are missing, the server explicitly logs a `[FATAL]` error and immediately halts (`process.exit(1)`).
2. **Standardization**: Updated `backend/config.js` to ingest values from `env.js` safely. Migrated all previous `MYSQL_*` environment variables to `STORE_DB_*` to establish a clean naming separation between databases.
3. **Safety Artifacts**:
   - Updated `.gitignore` to definitively block `.env` and `.env.local` files from Version Control.
   - Generated a templated `.env.example` file that perfectly models the expected schema with empty values to avoid accidental credential leaks.

## nLogin Architecture & Rules
A dedicated module (`backend/players`) was added to handle nLogin duties. It abides by the following architectural constraints:
1. **Separation of Concerns**: Maintains its own `mysql2` connection pool in `nlogin-db.js`, targeting only the host specified by `NLOGIN_DB_HOST`.
2. **No Store Auth Modification**: The native store authentication logic (`backend/auth`) and user tables are completely untouched. This integration functions exclusively as a peripheral lookup tool for admins.
3. **Data Sanitization**: The service layer (`backend/players/service.js`) utilizes `mapSafePlayer()`. This ensures that even if `SELECT *` was accidentally called, the API layer systematically destroys properties like `password`, `hash`, `token`, `session`, `salt`, and `IP`. It explicitly queries only the mapped columns dynamically generated by the `NLOGIN_COL_*` environment flags.

## Endpoints
The following endpoints were mounted under `playersRouter` inside `backend/index.js`, all rigidly secured behind the `requireAdmin` middleware block:
- `GET /api/admin/players/health`: Validates the `nLoginPool` by running `SELECT 1`.
- `GET /api/admin/players/search?q={query}`: Uses a `LIKE` SQL query to retrieve matching partial usernames.
- `GET /api/admin/players/:username`: Exact lookup for a specific player.
